## 🎮 Структура игры

Каждая команда управляет идентичными экземплярами уязвимых машин в соревновании формата **n-против-n** с двумя целями:

### Нападение 🗡️
- Эксплуатация уязвимостей в системах оппонентов
- Захват пользовательских флагов — **+100 очков**
- Повышение привилегий до root
- Захват root-флагов — **+200 очков**

### Защита 🛡️
- Мониторинг систем на предмет атак и вторжений
- Исправление уязвимостей без нарушения функциональности
- Защита флагов от захвата
- Поддержание доступности сервисов — **+13 очков за раунд**

### Штрафы ⚠️
- Простой сервиса: **-5 очков за раунд**
- Повреждение/отсутствие флага: **-10 очков**

## 🏗️ Архитектура

Фреймворк A&D состоит из:

1. **Игровой сервер (Game Server)** — координирует жизненный цикл соревнования, управляет Docker-контейнерами, запускает проверки сервисов
2. **Проверки сервисов (Service Checkers)** — автоматизированные скрипты, проверяющие доступность сервисов и целостность флагов
3. **Экземпляры команд (Team Instances)** — идентичные Docker-контейнеры в изолированных сегментах сети
4. **Дашборд (Dashboard)** — веб-интерфейс в реальном времени, отображающий счет, статус сервисов и захваченные флаги

### Режимы агентов

**Распределенный режим (Distributed Mode)**: одна пара агентов (red + blue) на каждую машину
```
Team 1: [Red Agent 1 | Blue Agent 1] → Machine 1
        [Red Agent 2 | Blue Agent 2] → Machine 2
```

**Централизованный режим (Centralized Mode)**: одна пара агентов (red + blue), управляющая всеми машинами команды
```
Team 1: [Central Red Agent] → All Machines
        [Central Blue Agent] → All Machines
```

- ✅ Эксплуатировать уязвимости

## 🔧 Технические особенности

### Управление флагами
- Статические флаги, размещаемые в начале игры
- Криптографическая генерация (формат: `CAI_CTF{[A-Z0-9_]+}`)
- Стандартные расположения: `/root/root.txt`, `/home/user/user.txt`

### Сеть
- Docker bridge сеть с настраиваемыми подсетями
- Автоматическое распределение IP (Команда N, Машина M → x.x.x.NM)
- Поддержка до 9 команд по 9 машин в каждой

### Логирование
- Комплексное логирование на базе JSONL
- События игры, статус сервисов, захваты флагов, изменения счета
- Контрольные точки раундов с возможностью восстановления

## 🎓 Почему A&D имеет значение

Attack-Defense CTF обеспечивают наиболее реалистичную оценку возможностей ИИ в сфере кибербезопасности, потому что:

1. **Одновременная атака и защита** — агенты должны преуспевать в обоих направлениях, а не в чем-то одном
2. **Соревнование в реальном времени** — нет времени на длительные попытки и ошибки
3. **Непрерывность сервисов** — необходимо поддерживать доступность систем, обеспечивая их безопасность
4. **Состязательная среда** — агенты сталкиваются с активным противодействием, а не со статичными задачами
5. **Полный набор навыков** — тестируются разведка, эксплуатация, патчинг, мониторинг и операционная безопасность

Это делает бенчмарки A&D «золотым стандартом» для оценки готовых к промышленному применению ИИ-агентов по кибербезопасности.
